# 工：面向个人的 AI 技能平台

“工”希望把不同用途的个人工具放在同一个工作环境中。用户可以从对话或明确的功能入口提出需求；平台提供模型、会话、基础资料与设备能力，各个 **Skill** 负责自己的业务流程、程序、资料和界面。

目前项目以**六爻占问、知人人物档案、知识库问答**为主要方向：既保留每项能力各自的专业流程，也探索它们怎样在用户授权下使用共同资料、衔接工作。

> **项目处于测试和持续设计阶段。**本公开分支基于较早的六爻 Android 工程，补充了平台设计文档和部分新版源码快照；它不能直接构建出与最新组合测试包等价的完整应用。[查看代码范围与交接说明](docs/gong/developer-guide.md)。

## 一、为什么做“工”

个人使用的软件往往围绕不同任务分散：在一个软件里记录占问，在另一个软件里维护联系人，再用其他工具查自己的资料。用户需要反复维护基本信息、适应不同入口；开发者也需要在多个项目中重复实现对话、模型配置和存储。

“工”的设计方向是把这些**共通能力交给平台**，让不同领域继续保留适合自己的流程：

- 用户可以在同一入口表达需求，也可以直接选择需要的功能。
- 提供精确输入的任务界面，例如记录真实起卦结果、编辑个人名片；不要求所有操作都依赖自由聊天。
- 将领域知识、业务步骤、程序工具和数据边界组织成 Skill，逐步支持独立维护与复用。
- 共同基础资料、界面风格与偏好未来可在用户授权下复用，避免重复填写；目前尚未完全统一。
- 以本地数据为基础，用户决定是否连接模型、知识库与云端服务。涉及私人资料或对外操作时，清楚说明范围并保留用户确认。

[了解完整产品思路](docs/gong/vision.md)

## 二、面向什么人、解决什么需求

| 使用场景 | 用户面临的需求 | 对应能力 |
| --- | --- | --- |
| 六爻学习与占问 | 希望记录真实起卦过程、获得可核对的盘面，理解依据并回看案例 | 六爻占问：起卦录入、程序排盘、规则与 AI 辅助解读、追问与复盘 |
| 个人与商务交流 | 联系方式、人物背景和交流记录分散；有活动或合作需求时想找到合适的人 | 知人：个人资料、多张名片、联系人、私人关系与交流记录、AI 整理和辅助找人 |
| 自己的资料与知识体系 | 有多套资料，需要围绕来源提问并追踪回答依据 | 知识库问答：连接已授权资料源，检索与引用；现有实现含 Dify Cloud 适配 |
| 希望提出产品反馈的人 | 遇到问题时，希望能描述具体场景并让开发者处理 | 技能反馈：记录 / 分诊思路；将来与具备代码能力的 AI 和开发者协作修复 |
| 同时使用多个能力的人 | 不想在不同工具间反复维护基础资料，希望将来跨领域回顾自己做过的事 | 共享资料、授权和平台级事件 / 周报是后续目标，当前尚未完整实现 |

## 三、主要 Skill

### 六爻占问：记录、计算、解释和复盘

围绕一次真实所问，记录实体起卦或用户主动触发的电子模拟，由程序完成明确的排盘和条件计算；AI 结合问题与计算结果辅助解读。用户可以查看原始记录和依据，后续对同一卦追问或保存相关案例。

设计重点是**程序计算、领域资料、模型解释和用户判断各有边界**：模型不能编造真实起卦结果，也不能改写盘面；卜宅需要明确对象、地点和阶段。

[六爻的设计意图、目标人群、需求与功能](docs/gong/liuyao.md)

### 知人：人物资料、名片与交流

帮助用户逐步记录认识的人及其背景，在交流、生活活动或商务合作中回忆共同话题、寻找可能合适的人。支持以一份完整资料制作多张名片，并将自己的私人关系、交流和约定与对外分享的内容分开。

AI 可以帮助整理用户主动提供的文字并提出待确认的资料；用户决定是否保存、如何分享和是否联系他人。当前活动邀请等功能以本地记录和模拟为主，不会自动向别人发消息。

[知人的设计意图、目标人群、需求与功能](docs/gong/zhiren.md)

### 知识库问答与其他能力

知识库问答面向用户自己的资料，目标是基于实际检索内容回答并给出依据。当前有 Dify Cloud 相关适配，需要用户自行配置授权、索引和可用服务；是否需要某种 embedding 取决于资料和检索需求。

此前决定暂不把联系人自动上传 Dify，这与知识库问答 Skill 是两件事。六爻中明确的干支、六亲等计算由程序完成；需要按问题检索、引用的资料才考虑知识库。

[知识库与数据边界](docs/gong/architecture.md)

## 四、一个任务如何通过平台完成

1. 用户在首页描述任务，或直接选择六爻、人物查询等明确模式。
2. 系统按当前状态和用户选择进入相应能力；自动识别需要可用模型，无法识别时应让用户选择或补充。
3. 需要准确输入时使用技能专用表单；程序先处理确定的计算或本地操作。
4. AI 可以整理输入、提出理解、解释已取得的结果，涉及资料更新等操作时保留用户核对。
5. 结果和必要背景保存在对应的会话 / 业务数据中；继续追问时尽量沿用原任务上下文。

例如“我想记录这次真实起卦并继续追问”进入六爻流程；“我想找成都喜欢徒步的人”可以检索知人中已有的资料。候选和模型输出都是辅助，不能推断对方一定有空或用户已经完成发送。

## 五、架构：平台、Skill 和数据

| 层次 | 负责的内容 | 当前情况 |
| --- | --- | --- |
| 交互 | 首页对话、手动选择、六爻和人物等专用页面 | 组合测试版已有，界面仍在持续整理 |
| 平台服务 | 会话、模型适配、本地服务、设备能力、资料与偏好、反馈 | 部分实现；共享资料、统一授权和数据迁移仍需完善 |
| Skill | 六爻、知人、知识库的说明、流程、工具和领域边界 | 已有描述文件、部分 manifest 与专用路由；通用安装和生命周期管理未完成 |
| 数据与外部服务 | 本地 SQLite、案例、规则 / 知识资料；按需连接模型和知识源 | 不同领域分别存储；联网调用、备份和跨技能访问依功能及授权而定 |

Android 测试版使用原生壳、WebView 和本地 Python 服务；Windows 电脑测试版通过本机服务和浏览器体验。两个版本的数据独立保存。当前这些组合实现不代表已经完成可直接安装任意第三方 Skill 的通用平台。

[技术架构与数据边界](docs/gong/architecture.md) · [Skill 设计与复用目标](docs/gong/skills.md)

## 六、当前进度与未完成事项

| 部分 | 状态 |
| --- | --- |
| 六爻 | 组合测试版已有多种起卦录入、排盘、模型分析、案例和追问相关实现；规则和各路径仍需持续验证 |
| 知人 | 组合测试版已有个人资料、多名片、人物记录、结构化整理和部分本地匹配 |
| 知识库 | 有 Dify Cloud 适配和引用相关实现；真实服务需要配置和联调 |
| 电脑体验 | 已提供 Windows 本机浏览器测试包；自动检查覆盖启动、人物保存与重读等核心路径，手机功能和完整交互尚未全部适配 |
| Skill 平台 | 已开始抽取说明、manifest、固定登记与部分工具接口；通用安装、第三方插件和完整跨宿主复用仍在规划 |
| 备份与协同 | 人物资料有未加密手动导出路径；个人云盘 / NAS 自动备份、自动恢复、跨 Skill 授权和平台级周报未完成 |
| 反馈修复 | 已有反馈 / 分诊相关设计，APP 不会自主改代码或自动发布；完整修复闭环尚待建设 |

测试版能运行不代表所有机型、真实服务、历史数据迁移或所有业务逻辑已验收。[开发路线与验证事项](docs/gong/roadmap.md)

1. 阅读 [整体设计和文档导航](docs/gong/README.md)，再分别阅读 [六爻](docs/gong/liuyao.md)、[知人](docs/gong/zhiren.md) 和 [Skill 设计](docs/gong/skills.md)。
2. 阅读 [开发者交接与代码地图](docs/gong/developer-guide.md)，了解公开基础工程与新版参考代码的区别。
3. 浏览 [平台及人物相关代码快照](reference/README.md)；这些代码依赖组合工程，不能单独构建出完整应用。
4. 早期公开六爻工程的构建、规则包格式、界面和测试说明保留在 [早期六爻 Android README](README-liuyao-legacy.md)。其中的版本和规则包行为不自动适用于最新组合测试包。

公开仓库不含完整组合构建所需的所有私有资源，也不提供签名密钥、用户资料或私有规则。**当前完整测试包包含私有业务规则，接收安装包的人可能将其提取。**公开可见不自动等于获得开源或商业使用许可；使用范围请与项目所有者确认。
