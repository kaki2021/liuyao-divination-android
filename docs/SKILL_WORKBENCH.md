# 六爻占问 1.3.0：统一对话与双技能工作台

应用继续使用“六爻占问”名称、既有应用 ID 和签名。已有卦例、规则与 API 设置的存储位置保持兼容。版本号为 1.3.0 / 10。

## 统一对话与按需界面

默认入口是一个对话框。首页保留新对话、历史、资料、人物档案和更多公共操作，六爻、知识库及反馈由消息意图触发，在会话内展开对应卡片。人物档案在桌面侧栏／手机独立面板管理，可反复关联到占问。

`chat_router.py` 先按明确表达、当前任务状态和最近技能识别意图，不为打开起卦卡片额外调用模型。普通“这工作适不适合”会先询问采用占卦还是资料讨论。含糊表述不自动当作起卦指令；讨论起卦方法、反馈重复起卦都不会新起一卦。下拉项仅用于纠正本条消息的识别结果。

明确要求新起卦时自动填写手机当前时刻并请求前台定位，太阳时由本地历法引擎换算。起卦地点和所问房屋地点分别保存。补录过去或时间未知的卦不代填现在的时刻与地点。打开已经保存的卦不会重新定位或更改其历史时间。

卜宅卡片可预填择地／范围核对／诊断／整改阶段、阳宅阴宅、起卦角色、入住状态、受益人、房屋代号及使用方案。预填依据是用户会话中的明确线索，并保持可编辑；角色未说明时使用“其他／尚未明确”，入住情况保持未知。多个房屋代号出现时不擅自选择第一个。程序不从文本编造六爻结果、GPS 或用户未提供的实际事实。

补充说明更新当前待完成卡片，已有手工改动优先保留。所有对话及任务关联持久保存；未完成的录入草稿单独保存，不用推测值覆盖原始手填。对话知道当前卦和所选分析，知识库讨论后可回到原卦，追问沿用原分析，不触发完整重跑。需要新起卦时单独生成新卡片。

`dialogue.py` 协调卡片、案例、知识库问答和反馈关联。`dialogue.js` 在消息内挂载既有专用录入与卦盘组件，复用验证过的计算、保存、分析和人物档案逻辑。当前内置两个技能，新增执行工具仍需开发接入；不支持任意外部脚本直接安装执行。

## 公共底座与技能

`liuyao_app/skills/` 内的两个内置技能包含说明与工具声明。它们使用公共的模型适配、手机定位、文件选择、原生导出与本地持久任务。技能文件作为资料读取，不能指定任意导入路径或执行任意脚本。

六爻模块保留专用录入、卦盘、正式规则和分析流程。知识库模块独立运行，无需先安装六爻规则。Android 原生草稿保存当前统一会话、未发送消息及起卦录入；同一会话的卡片草稿也保存在本机数据库中。

## 导入资料与问答

支持 UTF-8 / GB18030 的 TXT、Markdown，以及 DOCX 正文和表格文字。单文件不超过 4 MB，提取正文不超过 30 万字。DOCX 不解析图片和 OCR，PDF、扫描件应先转换为文字。压缩文档仅读取有大小上限的正文 XML，不解压到文件系统。

正文分为约千字片段，长段保留重叠。使用中文字及二元词、英文词和 BM25 排序进行本机关键词检索，每轮最多提供六个片段。该版本使用词面检索，表达差异大时可换用原文术语，不宣称语义向量召回。

联网模型获得本轮相关片段和近期最多八轮、约 28000 字的历史问答。历史对话全部保留，但不一定全部送入每次请求。历史 AI 回复只帮助理解追问，不能替代本轮原文。回复必须返回真实片段 ID；伪造引用、无引用的确定回答、无效 JSON 都不被采用。资料本身是否充分支持每条解释仍需用户核对，ID 校验不等于自动验证所有语义。

引用保存标题、文档 ID、版本、段号、SHA256 和原文。相同正文去重，移出检索只影响后续请求，历史快照仍保留。需要替换正文时移出旧资料并导入新资料；新正文有新的身份。资料仅保存在本机，不自动连接或同步 Google Drive。

无相关片段时由程序说明资料不足，不调用模型。离线演示只展示真实检索节选，明确标注没有调用模型。

## 技能反馈与自动修改范围

反馈由用户选择技能并填写标题和描述，不自动附带完整卦例、知识库或 API 配置。先保存反馈后再调用模型分诊；没有配置模型时仍可保存。反馈数据和改变仅作用于当前设备。

| 分诊类别 | 行为与状态 |
| --- | --- |
| 表达偏好 | 验证固定字段与选项，版本一致后自动应用，状态为“已更新本机技能” |
| 代码、界面或算法 | 生成修复任务及验收要求，状态为“待开发修复” |
| 正式规则或知识事实 | 保存核对要求，状态为“待核对资料” |
| 缺少信息 | 保存需要澄清的内容，状态为“需要补充信息” |
| 不需要改动 | 保存分析，状态为“已分析，无修改” |

可自动更新的字段为 `detail`、`layout`、`tone`、`clarify_first`。字段和枚举经过程序校验，反馈或模型生成的自由文本不会成为系统指令、代码、文件路径或环境配置。表达偏好应用于知识库回答、六爻报告整理和六爻连续追问，不能更改排盘、正式规则、来源、输出契约或历史报告。

每次更新追加一个技能版本，回退也追加新版本。并发处理以技能版本比较，过期改动不覆盖较新版本。反馈导出保留原始描述、提交时版本、各次处理结果以及代码类修复任务。

本版未接入远程维护 Agent，代码类反馈不会自动提交到 GitHub、执行代码修改、运行构建、合并或发布。若要形成跨设备的完整自动修复闭环，需要后续接入有仓库权限、测试环境和发布能力的维护服务。

## 持久化与接口

新增数据独立保存在应用数据目录的 `workbench.sqlite3`，不改变既有案例库。文档、对话、任务、反馈和版本均按本地 owner 隔离。

接口统一在 `/api/workbench/` 下：`skills`、`documents`、`chats`、`issues`、`jobs`、`active`。修改沿用本机会话、来源校验和幂等请求头。文档导入允许较大的 JSON，其他请求保持原上限。

任务结果与状态在同一数据库事务提交，避免丢失确认后再次扣费。原卦追问跨案例库和工作台库时，先持久保存回复关联；重启可采用已经保存的案例回复，不重新调用模型。尚未完成的请求标记为中断，不自动重放。Android 后台任务监测包含统一会话、两个技能及反馈处理。

## 检查

`liuyao_app.test_workbench` 覆盖资料格式、中文检索、隔离、引用、连续问答、删除后旧引用、幂等、任务中断、受限偏好修改、并发版本冲突及回退。

`android/tests/workbench_dom.cjs` 运行与 APK 相同的 Chrome 58 编译脚本，连接真实本地 HTTP 测试服务，检查完整界面流程及原生草稿恢复。模型调用使用测试替身，不消费真实 API。DOM 检查不代表实体 Android、GPS 或实际模型验收。

`test_dialogue.py` 和 `android/tests/dialogue_dom.cjs` 检查意图澄清、定位默认、卜宅推断、手工值优先、跨技能追问、人物档案隔离、补录旧卦以及重启恢复。旧组件的专项交互测试通过 `?legacy=1` 访问迁移前布局；APK 默认始终进入统一会话。
