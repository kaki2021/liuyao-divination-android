# 备份、发布与交接

## 测试包边界

目前构建是独立安装的 debug 测试包，使用独立包名，不能作为旧版的覆盖升级或自动迁移。不要卸载有资料的旧版。新包的手动人物导出路径和区县定位修复必须经过 CI 和真机检查；旧版本的导出路径在 Android 上可能无效。定位结果取决于手机与地理编码服务，不保证每次有区县。

## Google Drive 自动备份设计目标（尚未实现）

1. 用户首次授权个人云端位置；明确仅用于本应用备份所需的权限。
2. 从一致的本地数据快照产生版本化备份；明确定义资料、交流记录、约定、图片与其他技能数据的范围，默认不导出模型凭据。
3. 提供用户选择的加密或未加密模式。加密模式需口令派生密钥、认证加密、盐和版本参数；口令遗失无法解密。
4. 使用 Android 后台任务尽力每日执行，系统可能延后；上传失败后重试并显示最近成功时间，不把本地写入成功误报为云端成功。
5. 换机后检查云端备份，空设备恢复前确认来源和密码；已有本地数据时进行冲突处理，不能静默覆盖或重复导入。考虑删除标记、跨设备版本、原子性和恢复回滚。
6. 真实接入需 Google Cloud OAuth 客户端与发布签名，注册一致的包名及证书指纹；可靠的升级还需安全保管长期签名密钥。
7. 测试覆盖授权撤销、离线、服务限流、任务重试、备份校验、口令错误、中断、冲突及恢复。

NAS 仍是未来可扩展目标，当前不声称支持；Dify 暂不考虑。

## 给开发者的交付顺序

先固定包名及安全签名、完整可复现构建，梳理数据迁移和备份范围；再实现 Google Drive 授权、加密与定时备份、冲突安全恢复，最后完成真机和换机测试。涉及完整私有构建所需的非公开资源，请项目所有者通过受控方式单独安排。
