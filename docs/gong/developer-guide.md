# 开发者交接与代码地图

## 先理解两个代码范围

当前公开分支基于早期公开的六爻 Android / 知人 MVP，并另附最新组合测试版的一部分源码快照。最新 APK 通过私有组合构建流程在特定基础版本上应用多次集成，**公开分支不包含完整的最新组合源码或全部构建输入，不能直接构建出与该 APK 等价的软件**。

非公开部分包括私有领域资产和组合构建材料；请项目所有者另行决定授权。请勿为了让构建通过，把真实规则、口令、签名密钥或个人数据提交到公开仓库。测试 APK 本身包含私有业务规则，分发时也应考虑可提取性。公开可见不自动代表项目已授予开源使用许可。

平台参考快照中：`ai_router.py` 定义部分意图和路由校验，`dialogue.py` 管理会话和领域动作，`skill_registry.py` 描述固定 Skill 及偏好，`skill_runtime.py` 是部分领域调用入口；`skills/*/manifest.json` 展示组合测试版的实际技能描述。它们依赖未全部提供的宿主模块、服务、规则和静态资源，不要照搬后假定可执行。

## 先做什么

1. 阅读 [六爻设计](./liuyao.md) 和 [知人功能](./zhiren.md)，确认实际需求。
2. 对照本地接口、模型路由、人员和案例存储，列出组合构建与公开树的差异。
3. 与项目所有者确认完整源码、私有规则使用范围及签名 / 测试设备安排。
4. 先建立可复现的构建、基础测试和迁移策略，再增加新 Skill、共享数据和云同步。

## 验证程度

此前组合测试版已通过构建流程中的自动检查；这些检查不等同 Android 真机、真实模型 / 云端联调、旧版升级或换机恢复验收。不要把公开快照推断成已覆盖上述验证。
