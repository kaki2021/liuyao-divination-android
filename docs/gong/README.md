# 工：产品与开发者总览

“工”是一个面向个人的 AI 技能平台：用户通过统一的对话入口或专用页面完成任务，平台提供共通服务，不同 Skill 负责自己的流程、程序、领域资料和界面。目前重点包括**六爻占问、知人人物档案和知识库问答**。

## 为什么要做

个人处理不同事情时，往往需要在多个软件之间切换，重复维护个人资料和使用偏好。一个功能还可能同时需要准确计算、资料检索和自然语言理解。工希望保留领域工具各自的专业性，同时让会话、模型接入、个人基础资料和设备能力逐步形成共同底座。

设计不要求用户只靠聊天完成所有事情：用户可以描述任务，也可以直接进入具体功能；起卦记录和人物资料等精确操作使用相应界面。自动识别与模型输出需要校验，涉及资料更改和对外操作时保留用户确认。

## 平台有哪些能力

| 能力 | 服务的实际需求 | 设计重点 |
| --- | --- | --- |
| [六爻占问](./liuyao.md) | 学习六爻、记录真实起卦、排盘解读、追问与复盘 | 程序计算与 AI 解释分开；真实记录和规则依据可核对 |
| [知人](./zhiren.md) | 表达自己、逐步了解联系人、记录交流约定，组织活动或寻找合作对象 | 多张名片、私人关系、人工确认；先记录少量信息，再逐步完善 |
| 知识库问答 | 围绕自己授权的资料提问，并查看回答的来源 | 检索本轮资料、保留引用；当前有 Dify Cloud 适配，需要配置 |
| 技能反馈 | 描述实际问题，为开发者或具备代码能力的 AI 提供可处理的线索 | 反馈记录与修复分开；当前 APP 不会自行改代码 |

未来还希望在用户授权下共享基础资料、汇总不同 Skill 的事件，生成平台级周报或月报；这些是后续工作，不是当前已完成的跨技能服务。

## 一个典型流程

用户先描述“我想记录这一卦”或“找成都喜欢徒步的人”，也可以手动选择六爻或知人。系统进入对应 Skill；六爻让用户录入真实结果、由程序排盘，再由 AI 辅助解释；知人则查询已记录的人物资料，展示候选和依据。关键理解、资料更新和对外联系由用户核对并决定。

## 系统怎么组织

- **交互层**：统一对话、技能入口及专用页面。
- **平台层**：会话、模型、个人资料与偏好、设备能力、存储、授权和反馈等共通服务。
- **Skill 层**：每个领域的用途、步骤、输入输出、程序工具、资料及必要界面。
- **数据与服务层**：本地人物和案例数据、领域规则、用户授权的知识源，以及按需连接的外部模型。

这是目标分工；目前仍有一些业务按固定路由和专门页面组合，通用 Skill 安装、跨技能数据授权及独立运行需要继续完善。[架构与当前实现](./architecture.md) · [Skill 设计](./skills.md)

## 当前交付边界

- 组合测试版已有六爻、知人、知识库相关页面 / 接口以及统一对话入口；Windows 测试版可在本机通过浏览器体验，未适配所有手机功能。
- 知人的动态 / 邀请以本地记录和模拟为主，不自动向他人发送；平台级周报、跨 Skill 通用授权及云盘 / NAS 自动备份尚未完成。
- 本公开分支包含较早的六爻工程以及部分新版参考源码，**不能直接构建出与最新组合 APK / Windows 测试包等价的完整应用**。
- 公开仓库不包含私有规则、口令或用户资料；当前完整测试包包含私有业务规则，接收者可能提取。历史导出、签名和设备迁移仍须谨慎处理。
