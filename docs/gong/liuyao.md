# 六爻占问 Skill：从所问、起卦到解读与复盘

## 一、为什么设计六爻占问

六爻学习与实践涉及描述问题、记录起卦结果、排盘、理解规则、结合背景判断和事后复盘。对于使用者来说，这些步骤既要衔接，又各自有不同难点：刚入门的人不熟悉起卦记录和术语；已有经验的人可能需要重复查历法、排盘和整理案例；对一个问题继续追问时，又容易弄混原卦、补充背景和重新起卦。

**六爻占问 Skill 的目标**是把这一过程组织成可记录、可查看、可继续交流的工作流程：用户提出真实所问并记录起卦结果，程序完成明确的排盘和计算，AI 在用户问题、规则和计算结果的基础上辅助理解与解释，最后保留案例供后续追问、反馈和复盘。

这个设计也希望让初学者能沿着步骤理解六爻，让有经验的使用者能核对依据、保留自己的判断。它将传统六爻作为学习和思考的工具，不宣称可以验证占断必然准确，也不替用户作出决定。

## 二、给哪些人用

| 使用者和场景 | 可能遇到的问题 | 六爻占问希望提供的帮助 |
| --- | --- | --- |
| 对六爻感兴趣的初学者 | 不熟悉器具、步骤、术语和卦盘，不知道从哪里开始 | 提供起卦说明、分步骤录入、计算结果和必要的术语解释 |
| 想针对具体问题占问的个人 | 有一个想弄清或待定夺的问题，希望完整记录一次占问 | 从所问、实际起卦记录到排盘和辅助解读形成同一案例 |
| 使用实体工具起卦的人 | 已经用枚卜丸、太极丸或筹策起卦，希望保留实际操作过程 | 按所用方法输入真实结果，并保留原始记录及转换结果 |
| 有一定经验的学习者或卦师 | 想节省机械排盘时间，同时核对规则、盘面和解读是否合理 | 提供程序计算、可核对的条件与依据，以及可供参考的分阶段分析 |
| 需要持续追问和复盘的人 | 一个事情有后续变化，想回看原卦、追问或记录实际结果 | 保留案例、分析和交流历史，区分继续追问与重新起卦 |
| 研究具体地块或居住场景的人 | 想针对具体地点和目标，分清择地、诊断、核对方案等问题 | 提供卜宅相关的场景字段、分阶段记录和专门规则辅助；具体使用仍需结合实际情况 |

这些人群可能重叠。软件不假定用户一定依赖 AI；模型未配置时，部分本地记录和确定性计算仍有独立价值，具体可用范围以测试版和规则配置为准。

## 三、需求与功能如何对应

| 用户需求 | 产品功能与交互 | 当前状态 |
| --- | --- | --- |
| 说清想问什么 | 输入原始问题、背景和相关对象；AI 可提出可编辑的理解，关键歧义交给用户核对 | **测试版已有**问题输入、理解与补充流程；自动识别需要可用模型 |
| 不清楚怎么起卦 | 提供起卦须知、不同方式的操作说明与示例，帮助用户选择 | **测试版已有**说明和相关界面；不同设备的展示和滚动仍需实际验收 |
| 按自己使用的方式记录真实结果 | 支持枚卜丸、太极丸、蓍草 / 筹策、逐爻录入和用户主动触发的电子模拟；记录各方式的实际输入 | **测试版已有**这些方式的入口或处理；各方式需逐一真机回归，AI 不应代替用户编造实体结果 |
| 录入后自动排盘 | 将原始记录转换为六爻，计算本卦、变卦、干支、纳甲、六亲、世应、动变等确定性结构 | **测试版已有**排盘与规则计算；具体覆盖和正确性以代码、规则版本及测试为准 |
| 时间地点更符合实际 | 新起卦使用实际时间、地点及当地真太阳时；可授权定位或选择省市区县；补录历史卦时记录当时的时间地点 | **测试版已有**太阳时计算和地点选择相关实现；定位精度、历史时区和近似位置须核对，未知信息不应由当前值冒充 |
| 看懂盘面和判断依据 | 展示卦盘、已计算条件、相关规则及必要的术语说明；明确哪些是已知、未知或尚需判断 | **测试版已有**相关结果与说明；不能把所有传统规则都说成已程序化或已验证 |
| 围绕所问获得辅助解读 | 模型分阶段理解意图、提出取用 / 选择、解释并整理报告；对关键不确定条件要求用户补充 | **测试版已有**分阶段模型流程和校验；需配置可用模型，效果取决于模型与输入 |
| 对同一个问题继续交流 | 沿用已保存的原卦和分析追问，携带必要上下文；用户明确要求重析时才执行完整重分析 | **测试版已有**案例对话与追问路径；需继续验证上下文范围、耗时和模型调用行为 |
| 事情变化后记录新问题 | 明确区分“继续问原卦”和“另起一卦”；可在相关案例下保存新问题及其独立卦象 | **已有系列与案例相关实现**；具体界面与数据迁移以当前测试版实际行为为准 |
| 对照结果、积累经验 | 保留原始输入、计算 / 分析快照、补充背景和事后反馈，供用户重开案例复盘 | **测试版已有**本地案例、对话及反馈的相关能力；跨设备自动备份尚未完成 |
| 针对房屋或场地做专题分析 | 在卜宅中明确具体对象、地点、目标与阶段，区分择地、核对问题范围和验证方案 | **测试版已有**卜宅相关字段与规则处理；不等于软件完成现场勘察或建筑设计 |
| 想研究或复用六爻能力 | 将技能说明、工具接口、计算程序和必要资料整理成相对独立的 Skill，供其他 AI 宿主按能力调用 | **部分实现**描述、工具和特定宿主协议；完整通用插件安装与跨宿主开箱即用仍需开发验证 |

> “已有”指组合测试版中存在相关实现或界面，不表示全部机型、真实模型、所有规则及完整操作路径都已验收。

## 四、主要使用过程

### 1. 提出问题并记录真实起卦

用户先描述正在考虑的事情和必要背景，再选择枚卜丸、太极丸、筹策等方式，将实际操作的结果录入；也可以由用户主动选择电子随机模拟。程序按对应方式转换记录，保存原始输入和卦象。

**设计意图：**把用户真正问的问题和实际发生的起卦过程保留下来；不因 AI 对问题的理解、示例或演示结果而替换真实记录。

### 2. 排盘并理解依据

软件结合输入的时间、地点和卦象计算盘面，展示相关结构与条件；如果某个时间或前提未知，应保留未知状态。AI 在这些结果之上解释与问题相关的内容，用户可以查看依据和继续提问。

**设计意图：**减少重复计算，让使用者能区分程序给出的结构、用户提供的事实、规则依据及模型解释。

### 3. 继续追问、另起一卦或事后复盘

对同一卦想了解细节时，用户打开原案例继续对话；问题发生变化、需要重新占问时，再选择另起一卦并保留关联。事情有结果后，用户可记录反馈，与当时的输入和解读一起回看。

**设计意图：**让一次占问成为可以追踪的案例；普通追问不应自动重新起卦或反复重跑完整分析，也不应把后来发生的事改写成当初已经知道。

### 4. 卜宅：针对具体地点、对象与问题

如果用户是在多个候选地点中选择，先记录候选地点、受益对象和想解决的问题；如果是在核查现有问题或一项整改方案，也分别说明当前阶段和方案。起卦位置与实际房屋位置可能不同，应由用户确认。

**设计意图：**将具体问题和适用范围说清楚，使不同阶段的记录可以相互关联、分别判断。软件只辅助记录与分析，不代替实地考察和专业设计。

## 五、程序、AI、知识资料和用户各做什么

| 角色 | 负责什么 | 边界 |
| --- | --- | --- |
| 用户 | 提供真实起卦结果、所问及背景，确认重要理解，决定如何使用结果 | 用户可以修改 AI 对问题或主体的理解；未知信息保持未知 |
| 确定性程序 | 依已明确的规则处理历法、卦盘及适合计算的条件 | 输出应可核对、留存版本；不确定或未实现的判断不能伪装成确定结果 |
| 领域规则和资料 | 提供六爻 / 卜宅专业依据、适用条件、说明和来源 | 应维护版本与适用范围；不是每条说明都必须写成程序 |
| AI | 理解所问、提出可编辑的理解，结合盘面和相关依据组织解读、报告及追问 | 不能改写起卦记录和确定性盘面，不能把推测或缺失条件说成事实 |

例如干支、六亲、世应这类有明确转换过程的内容应由程序处理；专业原理或需要按问题查阅的资料，才可能需要知识库检索。是否引入六爻专用 RAG，应看资料和使用需求，而不是先假定所有六爻内容都要做 embedding。

## 六、时间、资料和规则如何处理

- **起卦方式尊重用户选择：**实体工具的实际结果由用户录入；电子模拟由用户主动触发。软件可解释不同方式及其记录要求，不将模拟结果包装成实体起卦。
- **时间与地点应对应当次占问：**新卦使用实际时刻和当地太阳时；历史卦使用历史时间及当地时差。省市区县位置是参考，缺失信息不应凭空补齐。
- **人物与占问资料按需填写：**是否关联自己或他人、出生资料及相关背景应由用户决定；资料不因关联人物就自动全部用于每次分析。
- **原始数据和解释分开：**保留用户输入、盘面、背景、模型解释及反馈的区别；后续修改和重分析应可追溯。
- **规则资产分开管理：**公开工程、私有规则、测试包的打包范围可能不同；不得在公开仓库提交私有规则、口令或真实案例。当前测试安装包包含私有规则，分享时应注意可被提取。
- **用途与局限：**这是传统文化学习、案例记录与思考辅助工具，结果不能保证准确，也不替代对实际情况的核实或专业意见。

## 七、与“工”平台及其他 Skill 的关系

六爻占问是“工”的一个领域 Skill。平台提供统一对话入口、模型接入、会话和设备能力；六爻负责自己的起卦、计算、规则、案例与解读流程。需要更精确的录入时进入六爻专用界面，不要求所有操作都用自由聊天完成。

未来，用户可以在明确授权后选择自己的公共基础资料或知人中的特定人物资料，避免重复录入；当前不应假定不同 Skill 已经自动共享全部数据。知识库问答是另一能力，六爻是否调用某项知识检索需要清楚界定资料、权限和实际接口。

六爻已有 Skill 说明、工具与特定宿主协议；将其脱离当前 APP 复用是持续目标。不同宿主的运行能力、依赖、规则授权及校验流程不同，不能把已有描述文件等同于所有平台都可直接安装。

## 八、后续需要验证和决定的内容

- **完整回归：**逐项验证五种起卦方式、原始记录与转换、太阳时、城市选择、历史时间、卜宅与追问流程。
- **规则与计算边界：**逐条判断哪些需要确定性计算、哪些属于 AI 解释或领域资料；旧核对表中的“未登记”不自动等于要编程。
- **AI 质量与成本：**检查问题理解、关键条件澄清、依据对应、输出格式、失败恢复和普通追问携带的必要上下文。
- **案例与备份：**验证连续对话、关联案例和反馈；明确跨设备保存范围，云端 / NAS 自动备份及恢复尚未完成。
- **跨宿主复用：**整理独立依赖、工具契约、版本、测试与私有规则授权，验证其他 AI 宿主是否可以运行。
- **知识检索：**先确定真正需要检索的六爻资料与引用方式，再决定是否建设专用知识库或 embedding。
