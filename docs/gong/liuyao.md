# 六爻占问 Skill：记录、计算、解释和复盘

六爻是“工”的核心领域能力之一，源自原有六爻 Android 工具。目标是保留真实起卦过程和可复核的盘面，让用户围绕同一个案例理解、追问和复盘；并将领域能力逐步整理为可以在不同 AI 宿主调用的 Skill。

## 用户流程

1. **明确所问**：用户描述问题和背景；系统可根据原话提出可编辑的理解，主体、对象、用途等关键歧义由用户确认。
2. **记录起卦**：支持枚卜丸、太极丸、蓍草 / 筹策、逐爻录入及由用户主动触发的电子随机模拟；以实际测试版提供的界面与结果为准。不能由 AI 自行编造卦象或实际器具结果。
3. **时间与地点**：新起卦按实际时刻、当地位置计算太阳时；省市区县参考位置属于近似值。补录历史卦使用当时真实时间、地点与时差，未知项保持未知，不用当前值冒充。
4. **程序排盘与条件计算**：按规则生成卦象、干支、纳甲、六亲、世应、动变等结构，并按实现计算适用的条件；保存原始输入、结果及规则 / 算法版本。实际覆盖范围以代码、规则包和测试为准。
5. **AI 分阶段辅助解读**：结合用户所问和确定性结果，执行理解意图、取用与选择、解释、整理报告等步骤。AI 可以提出需要核对的理解，不能改写程序生成的盘面或把推断当作事实。
6. **保存、追问与复盘**：原始记录、分析结果和案例历史分开保存。继续追问通常沿用原卦及已有分析，不自动重起卦或完整重跑；另起新卦和明确要求重新分析是不同操作。

## 程序、AI 和知识资料各做什么

| 部分 | 职责 | 边界 |
| --- | --- | --- |
| 确定性程序 | 卦盘、历法、已明确的配对和计算条件 | 无法确定的判据保持未知；不是所有规则都应硬编码 |
| 规则与领域资料 | 给出判断依据、专业原理及适用边界 | 维护版本和来源；私有规则不放入公开仓库 |
| AI | 理解问题、提出可编辑理解、联系已给出的计算和规则解释 | 不替用户虚构输入，不更改确定性结果，不承诺准确率 |
| 用户 | 提供真实起卦与背景，确认关键条件 | 系统辅助学习与判断，不代替用户决定 |

例如干支、六亲、世应这类明确计算属于程序内容；需要按问题查找、引用和解释的专业资料才可能需要知识检索。是否增加六爻专用知识库应由具体资料和任务决定，当前不宣称所有规则都已接入 RAG。

## 卜宅

卜宅是六爻的一个专题流程，例如择地、核对范围、诊断或措施核对；阶段、对象和地点应由用户明确或确认，不把手机定位直接当作所问房屋地点。不同阶段需要哪些信息和规则，应继续由领域维护者校验。

## Skill 化与当前实现

- 已有六爻 Skill 说明、工具与运行接口的组合实现，并在测试版中打包相关定义；领域计算与模型分析仍由现有应用代码及宿主能力承担。
- 特定 AI 宿主若具备持续双向进程交互，可按对应宿主协议执行多阶段分析；其他宿主可能只支持部分工具或直接解释，不能宣称相同校验均已执行。
- “脱离本 APP 复用”是目标，不等于所有宿主都开箱即用：依赖、数据目录、规则授权、输入输出与错误处理仍需逐项适配验证。
- 旧规则核对中的“未登记实现”不自动等于必须写代码；要先判断它属于计算、解释规则还是不适用的条目。
