# 按知识库重设计判断规则

日期：2026-10-08。状态：已实现条件核对与页面改造；完整旺衰、作用先后、化空具体影响和精确应期仍保留为系统判据缺口。

## 结论

应把本次主问的功能关系、各爻状态、作用条件、主体得失与目标成败分别表达。给“化空”增加几个可调系数，仍不足以解决当前模型把不同性质的关系合成一个分数的问题。下面的架构是软件设计建议，并非原书给出的评分公式。

## 现有代码与原理的差距

| 当前行为 | 需要重设计的部分 |
|---|---|
| `change_analysis.py` 命中化空即计入固定 `CHANGE_EMPTY` 权重 | 化空识别事实与具体影响分开；未形成判据时保留待判断 |
| `strength_engine.py` 把日月、空破、动变与外来贡献合计并限制在0—10 | 旺衰证据、当前作用状态、对目标的方向和时间条件分别记录 |
| `comprehensive_analysis.py` 对每个目标遍历其他来源；发动或实验暗动来源累计生克及配对贡献 | 全盘关系作为候选结构保留，再按本问目标核对适用关系；不能宣称候选作用同时成立 |
| `relation_effect_engine.py` 把三形、六害标签映射到统一作用权重 | 保留配对类别与方向，具体解释须有场景、整体判断和适用条件 |
| 同类用神按综合分加发动、持世加分排序，首项成为选中项 | 先按用途匹配，再说明多现候选选择理由；判据不足保留多候选，不默认强者更对应问题 |
| 模型接收 `ACTIVE_EFFECT_*`、`PRIMARY_USE_LINE` 等服务器字段 | 同步修改投影契约，区分计算结果、候选作用、条件通过的作用和 AI 解释，不能只改界面标签 |

## 新判断结构

1. **意图与取用**：记录原问、实际对象、功能、关切、主体参照及对应的用户文字。AI抽取属于候选解释，用户可直接修正。只追问会改变取用或结论的必要现实条件。
2. **结构与状态**：程序计算盘面、日月关系、动静、原爻旬空、变爻旬空、月破等独立字段。月令旺相不直接等于综合旺相；无可执行综合判据时展示证据，不自动下标签。
3. **条件作用**：保留来源、目标、变爻、作用方向和本问功能，核对条件、例外及互斥关系。事实可枚举，成立的作用不能凭配对全部自动累加。
4. **结论与边界**：分开回答目标能否达到、主体得失及有关时间条件。结论必须引用适用的作用和前提；没有完整判据时降低对应结论范围，不以一个总分代替判断。

以上层次不是物理能量传播公式，也不要求所有问题都使用身位或所有关系。

### 规则数据

| 字段 | 含义 |
|---|---|
| 标识与版本 | 规则、资料、判断实现各自版本；保持与历史记录可追溯 |
| 场景与角色 | 适用于什么问法、对象用途、起卦身份和阶段 |
| 结构匹配 | 哪些支、爻、日月或动变结构出现了 |
| 条件与例外 | 显式条件，逐项采用满足／不满足／未知；未知不能当作不满足或默认满足 |
| 来源与目标 | 原爻、变爻、受作用爻及其与本问的关系 |
| 作用结果 | 状态解释、方向、限制或提示；不强制每条规则带分值 |
| 互斥与先后 | 只有出处或核准案例支持时才定义；未解决的冲突保留分支，不能循环引用结论证明前提 |
| 出处与采用状态 | 原书章节、定位、采用说明；分别标记原文说明、已实现判据、待实现、待案例验证 |

未知须进一步区分：用户事实缺失、已知资料尚未展开、系统缺少判据、来源冲突。只有第一类且会改变结果时，才向用户补问；不能要求用户补齐系统的旺衰算法。

化空首先只记录“某动爻所化地支在起卦日所属旬为空”。对哪个目标影响、当前能否作用、是否与月破并存、以后何时满足什么条件，属于后续判断。本次资料不足以把这些问题写成统一扣分或精确发力日期。

## 页面设计

沿用问卦／档案／规则三处主导航；结果仍为解卦结论／专业分析／卦盘与计算。Log继续放在重新解卦右边的按钮里。

**规则页**沿用现有三个分区。建议把“参数调校”改成“判断规则”，另两项保留“使用原理”“规则包”。

- 规则列表只用“规则／当前策略”两列；不恢复用户已要求删除的类型列。搜索和场景筛选放在表格上方。
- 点开规则，在同页展开适用场景、条件、例外、作用对象、处理结果和出处；原文定义不做任意数值编辑。
- 提供情景试算：改真实场景条件后，比较命中、未命中、未知及结论范围怎样变化。
- 原有分值调校收在“实验评分”折叠区，明确其影响位置和缺乏校准的事实。
- 用历史案例对照原问、当时输入、适用规则、原判断和后来反馈。显示误取用、错误作用、条件遗漏等问题，再判断是否需要调参；不预设模型已有成功率。

**专业分析**保持三块紧凑表格：

| 区块 | 主要列 | 用途 |
|---|---|---|
| 意图与取用 | 用户原意／AI理解／取用与理由 | 检查是否理解错问题、取错象；提供修正入口 |
| 爻的状态与作用 | 爻／日月与动变状态／对本问作用 | 先显示主用、主体和有关来源；其余爻展开查看 |
| 成立条件与限制 | 条件／状态／影响 | 集中展示成立前提、待补事实、结论限制和系统未实现能力 |

出处和推演细节按行展开；研究审计与模型原始回复仍只在Log。普通解卦结论保持简短，只带影响行动的关键现实条件。

## 系列与实施顺序

系列共享用户确认的背景和方案版本；每个节点保留自己的原问、起卦时间、盘面和规则快照。父节点的 AI 判断只是带来源的参考，不自动变成子节点事实。细问改变用途或目标时重新取用，不直接继承父卦旺衰、结论或用神。

先建立规则出处、条件状态和作用证据数据，再在专业分析中显示；随后逐条把有明确判据的规则实现，并用有现实反馈的案例核对。整体改为新默认判断方式前，需要覆盖多现取用、空破并存、局部例外、生克目标冲突和资料缺失等情况。

旧实验模型和历史报告保留版本，重新分析由显式操作生成新版本。数值如要继续发展，应在规则含义固定后单独做案例校准，不能用同一系列的关联问题同时作为调参样本和验证样本，也不能把 AI 自己的结论当作实际结果。

实现记录：新增独立条件核对，按用途保留多现候选，新的 AI 解释不接收累计实验作用分；规则页提供条件表、情景试算、案例反馈对照及随软件内置的可导出计算逻辑。70项参数保留在实验评分区；新分析保存逻辑说明和摘要快照，历史记录不改写。
